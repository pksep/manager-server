# manager: решения и уточнения

Редакция 0.2 · 10.09.2026.

Владелец разрешил перейти к выполнению: «Хорошо давай переходим к выполнению приступай».
Выполнен локальный этап виджета. Рабочие ветки остаются `manager`.
Демо использует 08:00–18:00 пн–пт, все три контакта и отправку после формы;
производственные значения открытых вопросов ниже отдельно не подтверждены.
Документ сохраняет договорённости между этапами. Изменение решения включает
дату, основание, затронутые файлы требований и влияние на критерии приёмки.
Статус проекта: первая фаза принята пользователем; 11.09.2026 разрешены push
веток `manager` и переход ко второй фазе — сервису между виджетом и СЭП Чатом.

## Подтверждено пользователем

| ID | Решение |
| --- | --- |
| R-01 | Два новых репозитория: `pksep/manager-client` для виджета и `pksep/manager-server` для сервиса |
| R-02 | Название задачи `manager`; ветка `manager` зафиксирована в контексте задачи |
| R-03 | Виджет должен быть открытым проектом |
| R-04 | `sep-bot-api` не используется; нужен специализированный сервис |
| R-05 | Сервис принимает сообщения из виджета и чата, поддерживает дальнейшие подключения платформ |
| R-06 | Используются существующие возможности чата: топики, сообщения, файлы, вложения и UI |
| R-07 | Все менеджеры с предоставленным через ЕРП доступом видят все обращения и могут отвечать |
| R-08 | Первый ответ автоматически назначает ответственного, последующие ответы его не меняют; доступно ручное назначение другого менеджера |
| R-09 | Менеджер видит прежние обращения клиента, клиент их не видит |
| R-10 | Клиент сопоставляется между платформами по телефону/email и ищется в контактах ЕРП |
| R-11 | «Добавить в СЭП» означает синхронизировать клиента с ЕРП |
| R-12 | Виджет целиком скрыт, если связь с backend-сервисом недоступна |
| R-13 | Кнопка 60×60, иконка 24/chat, меню на наведении, социальные ссылки из конфигурации |
| R-14 | Окно 418×640 с радиусом 20; шапка 76; редактор 120; остальные размеры и цвета сохранены в WIDGET_SPEC |
| R-15 | При первом открытии три сообщения из конфигурации; после первой попытки отправки показывается контактная форма без истории и редактора |
| R-16 | После формы используются стандартные сообщения и аватары; статус оператора зависит от расписания Москвы |
| R-17 | Сначала изучение кода и утверждение дополняемого плана, затем три этапа реализации |

Важная интерпретация R-10: совпадение реквизитов и подтверждённая личность
различаются. По уточнению от 14.09.2026 карточка связывается автоматически,
когда одновременно совпадают нормализованные телефон и email.
Для клиента объединение карточек никогда не расширяет доступ к истории.

## Открытые продуктовые решения

| ID | Что нужно решить | Предложение / текущее основание | Когда нужно |
| --- | --- | --- | --- |
| D-01 | Работа до 16:30 или 18:00; дни недели | В исходном ТЗ оба варианта; timezone Europe/Moscow подтверждён. Вопрос направлен пользователю, ответа пока нет | До готовности статуса и публикации конфигурации |
| D-02 | Обязательны ли все три контактных поля | В принятой первой фазе обязательны имя, телефон и email; сервис сохраняет настраиваемую политику | Зафиксировано для текущего сценария |
| D-03 | Первое сообщение отправляется до формы или после | Принят реализованный сценарий: текст и файлы отправляются после контактов. Отдельно подтверждена прямая отправка выбранных файлов только в виджете | Зафиксировано для текущего сценария |
| D-04 | Когда связывать клиента автоматически | Полное совпадение нормализованных телефона и email использует того же клиента и открытый чат. Один совпавший реквизит остаётся кандидатом; история посетителя ограничена своей сессией | Уточнено пользователем 14.09.2026 |
| D-05 | Какие платформы должны принимать сообщения в первом выпуске | Подтверждён первый сайт npoamotiv.ru. Социальные ссылки входят в виджет; двусторонние интеграции имеют отдельный список и критерии | До оценки адаптеров |
| D-06 | Открытая лицензия и распространение общих компонентов | Лицензия пока не выбрана; у yui явная лицензия не найдена, у chat_client LICENSE пуст. Локальное переиспользование выполнено по прямому указанию владельца; лицензию выбрать до открытого релиза | До публикации общего кода |
| D-07 | Тексты, гарнитура и недостающие размеры | Три приветствия, название/аватар компании, фон истории, нижний отступ формы/плашек, размеры инпутов и положение кнопки ещё не закреплены | На проверке макета |
| D-08 | Жизненный цикл завершённого обращения | Предлагается OPEN/CLOSED; нужно определить, когда продолжать старый диалог, а когда создавать новый | До завершения серверной модели |
| D-09 | Лимиты вложений и сроки хранения | Конфигурируемые ограничения для гостя; не наследовать автоматически внутренние 600 MiB | До открытия публичного приёма |
| D-10 | Связь после ухода с сайта | Контакты собираются; автоматические письма/SMS не включены в первый выпуск. Сотрудник сможет связаться по оставленным данным | При добавлении автоматических уведомлений |
| D-11 | Автоматическая загрузка контактов в ЕРП | Подтверждено действие менеджера «Добавить в СЭП». Фоновое создание каждого посетителя не утверждено | Перед добавлением такой автоматизации |

Не требуется собирать ответы на весь список перед началом независимой вёрстки.
Зависимое поведение не объявляется согласованным по истечении времени ожидания.

## Технические предложения для утверждения с планом

| ID | Предложение | Основание |
| --- | --- | --- |
| A-01 | Отдельный сервис обращений и существующее хранение сообщений/медиа чата | Пользовательский сценарий и готовые сервисы chat_server |
| A-02 | GROUP + типизированное назначение внешнего обращения | Совместимость с существующей моделью топиков и участие менеджеров |
| A-03 | Ограниченный внешний профиль автора в чате | Обязательный senderUserId; стандартный показ имени/аватара |
| A-04 | Общие отображающие компоненты в существующем sep_yui | Редактор уже общий, MessageBubble пока связан с приложением |
| A-05 | Загрузчик + iframe для виджета | Глобальные стили, шрифты, Teleport и измерение viewport в yui |
| A-06 | Менеджерские действия через авторизованный backend чата | Единый вход сотрудника и единая проверка топиков |
| A-07 | Отдельный ключ права ЕРП и обновление полномочий | Название роли не заменяет права; нужен отзыв текущих подписок |
| A-08 | Постоянные задачи доставки, дедупликация и восстановление | Текущий publisher и запись сообщений не дают общей транзакционной гарантии |
| A-09 | Повторяемая синхронизация ЕРП через канонический ContactService | Создание сохраняет журнал действий; ключ защищает от дубля при таймауте |
| A-10 | Ограниченный доступ к файлам обращений поверх существующего хранилища | Гостевой доступ и права менеджеров нельзя выразить общей публичной ссылкой |

Это не дополнительные репозитории. Изменения существующих библиотек и сервисов
выполняются в той же задаче `manager`, по одной ветке и не более одного PR
на затронутый репозиторий.

## История

11.09.2026, редакция 0.5: добавлены точные кандидаты контактов ЕРП, явная связь
и повторяемая команда создания через ContactService/ActionsService. Инициатор
берётся из erpActors доверенного снимка, ЕРП проверяет живые права. Общая история
после связи с одним контактом открывается только менеджерам. Производитель
снимков и новый раздел остаются отдельным следующим участком.

11.09.2026: первая фаза отправлена в ветки `manager`. Для первого участка второй
фазы реализован долговечный журнал внутри транзакции MessagesService, доставка
из него опросом с последовательностью на обращение и WebSocket до виджета.
Файлы используют S3 чата и отдельную проверку доступа. Внутренний контракт v1
проверяется сквозным тестом двух серверов. Редактирование/удаление пока явно
ограничены. Производственная синхронизация ЕРП и роли не выданы за завершённые.
Подробности: [PHASE_2_PROGRESS.md](PHASE_2_PROGRESS.md).

телефона и email без подтверждения контактов. Если площадка не передаёт реквизиты,
клиент определяется её ID внутри подключения; менеджер может связать сохранённый
контакт через штатную ЕРП. Подробности и ограничения: [CHANNELS.md](CHANNELS.md).

До внешнего запуска: ключи и приёмка площадок/SmartCaptcha, согласованные версии
и миграции, успешные обязательные проверки ЕРП и производственные значения D-01–D-03.
