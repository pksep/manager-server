# WhatsApp для раздела «Клиенты»

Канал использует официальный WhatsApp Cloud API и отдельный номер компании. Покупать или переносить личный номер для разработки не требуется. Для первого внешнего теста подходит тестовый номер, предоставленный Meta в кабинете приложения.

## Что работает в первой версии

- Входящие личные сообщения, фотографии JPEG/PNG и документы передаются в существующие обращения через общую очередь Manager.
- Имя и телефон отправителя используются для карточки клиента. Повтор одного webhook не создаёт повторного сообщения. Несколько сообщений в одном webhook обрабатываются отдельно.
- Оператор отвечает в исходный канал. Изображения ограничены 5 МБ, документы 20 МБ, текст делится по 4096 символов. Файлы проходят существующую проверку безопасности.
- Свободный ответ доступен до истечения 24 часов от времени последнего сообщения клиента в WhatsApp. Повтор старого уведомления не продлевает окно. Проверка выполняется перед сохранением ответа и перед фактической отправкой из очереди.
- Если соединение оборвалось после отправки, операция становится неопределённой и автоматически не повторяется. Менеджеру нужно проверить переписку перед подтверждением повтора.

Шаблонные сообщения, рассылки, голосовые сообщения, видео, звонки, группы, импорт старой истории и получение аватара через API в эту версию не входят. Для неподдерживаемого входящего вложения оператор увидит пояснение. Статусы `sent/delivered/read` принимаются как служебные события и не создают сообщений. Состояние доставки в Manager подтверждает принятие запроса API Meta, а не прочтение сообщения клиентом.

## Настройка Meta

1. Выберите отдельный номер компании с доступом к SMS или голосовому подтверждению. Для первого теста можно оставить тестовый номер Meta. Не регистрируйте личный номер вместо него.
2. В [Meta Business Suite](https://business.facebook.com/) подготовьте бизнес-портфолио компании с доступом администратора. Проверку компании выполняйте по требованиям, которые покажет Meta для выбранного аккаунта.
3. В [кабинете разработчика Meta](https://developers.facebook.com/) создайте приложение с WhatsApp Cloud API и свяжите его с бизнес-портфолио. Пройдите API Setup, добавьте и подтвердите номер. Точные названия экранов зависят от версии кабинета.
4. Сохраните **WhatsApp Business Account ID** и **Phone Number ID**. В конфигурации `accountId` означает Phone Number ID, это не сам телефон.
5. Создайте серверный токен системного пользователя с необходимыми правами `whatsapp_business_messaging` и `whatsapp_business_management` и доступом к WhatsApp-аккаунту. Короткий тестовый токен API Setup подходит только для первичного тестирования. Срок действия и отзыв токена контролирует администратор Meta.
6. Сохраните App Secret приложения и токен в защищённом серверном хранилище. Создайте отдельный случайный Verify Token длиной 32–128 символов из букв, цифр, `_` и `-`. Не присылайте ключи и коды подтверждения в переписку и не добавляйте их в Git.
7. Подключите способ оплаты и проверьте действующие цены в кабинете Meta перед реальной эксплуатацией. Приложение не считает и не гарантирует стоимость сообщений.

## Настройка Manager

В защищённое окружение Manager добавьте:

```dotenv
MANAGER_WHATSAPP_TOKEN=значение_из_защищённого_хранилища
MANAGER_WHATSAPP_APP_SECRET=секрет_приложения_Meta
MANAGER_WHATSAPP_VERIFY_TOKEN=случайный_секрет_подтверждения_callback
MANAGER_PUBLIC_URL=https://manager.pksep.ru
```

В действующий JSON-файл `MANAGER_CHANNELS_PATH` добавьте запись. Остальные подключения должны остаться в этом же списке, иначе Manager отключит отсутствующие в конфигурации каналы.

```json
{
  "id": "whatsapp-company",
  "platform": "whatsapp",
  "name": "НПО Автомотив в WhatsApp",
  "accountId": "PHONE_NUMBER_ID",
  "businessAccountId": "WHATSAPP_BUSINESS_ACCOUNT_ID",
  "apiVersion": "VERSION_FROM_META_API_SETUP",
  "enabled": true,
  "tokenEnv": "MANAGER_WHATSAPP_TOKEN",
  "appSecretEnv": "MANAGER_WHATSAPP_APP_SECRET",
  "webhookSecretEnv": "MANAGER_WHATSAPP_VERIFY_TOKEN"
}
```

Замените три значения идентификаторов и версии реальными данными из Meta. Версия имеет формат `vXX.0`; версия в тестах не является рекомендацией для production. В конфигурационном файле хранятся только имена переменных с ключами.

Обновите Manager Server, Chat Server и Chat Client согласованными изменениями этой задачи. Примените миграцию Manager `012_whatsapp.sql` штатной командой `bun run migrate:up` до запуска обновлённого сервера. Миграция расширяет список каналов и добавляет время входящего сообщения; переписка не удаляется. Откат откажется, если уже сохранены WhatsApp-подключения или маршруты.

Проверьте ключ и принадлежность номера аккаунту:

```sh
bun run channels:check whatsapp-company
```

Команда использует серверное окружение. Перед запуском должны быть загружены секреты и переменная `MANAGER_CHANNELS_PATH` обычным способом вашего развёртывания.

## Callback

После выкладки обновлённого Manager в настройке Webhooks приложения Meta укажите:

```text
Callback URL: https://manager.pksep.ru/v1/channels/whatsapp/whatsapp-company
Verify Token: значение MANAGER_WHATSAPP_VERIFY_TOKEN
Webhook field: messages
```

Адрес одинаков для подтверждения GET и уведомлений POST. Входящие POST проверяются по `X-Hub-Signature-256` и исходным байтам тела с использованием App Secret. Verify Token используется только для подтверждения URL и не заменяет проверку подписи. Прокси не должен менять тело запроса.

После подтверждения URL подпишите приложение на WhatsApp-аккаунт:

```sh
bun run channels:subscribe whatsapp-company
bun run channels:status whatsapp-company
```

`channels:subscribe` оформляет подписку WABA, но не создаёт приложение, номер, платёжный метод и не настраивает callback приложения автоматически. На текущем production адрес ещё не объявляется рабочим до выкладки.

## Проверка после подключения

С другого телефона отправьте текст и небольшую фотографию на номер компании. В «Клиентах» должны появиться сообщение, источник WhatsApp и телефон. Ответьте текстом и фотографией из СЭП и проверьте получение на телефоне. Повторная доставка webhook не должна удвоить переписку. В случае ошибки проверьте `channels:status`, не повторяйте неопределённую отправку до проверки телефона клиента.

Без аккаунта и токена Meta проверяются изолированные сценарии с тестовым API, реальными временными PostgreSQL/Redis/RabbitMQ и подменённым Chat API:

```sh
bun run typecheck
bun run test
bun run test:whatsapp
bun run test:bots
```

Эти проверки не доказывают регистрацию номера, наличие разрешений Meta, оплату или доставку через настоящий WhatsApp.

Официальная документация: [Cloud API и настройка аккаунта](https://www.postman.com/meta/whatsapp-business-platform/overview), [отправка сообщений](https://www.postman.com/meta/whatsapp-business-platform/folder/o48mro7/messages), [правила окна ответа](https://whatsappbusiness.com/policy/).
