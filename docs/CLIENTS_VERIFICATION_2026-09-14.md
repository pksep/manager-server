## Отдельный интерфейс контактов ЕРП

По запросу пользователя поднят http://127.0.0.3:4315/contactbase. Используются
штатные BaseContacts, TableContacts, ModalContact, sep-yui и обычный API контактов
через дополнительный локальный процесс 4503. Контракт синхронизации 4502 и API
интерфейса подключены к той же manager_erp_local. Производственные окружения
не подключаются. Существующий тестовый сотрудник сохранён; вход автоматический.

Ранее контакт без компании находился по id, но отсутствовал в общем списке:
where на Companies неявно требовал наличие связи. Требование показать созданных
из обращений клиентов выполнено изменением канонического ContactService:
без фильтра компания необязательна; при фильтре по компании/типу отбор сохранён.
distinct исключает удвоение общего числа из-за нескольких компаний. Исследованы
ContactsController, ContactService, схемы DTO, stores/contacts, BaseContacts,
TableContacts, ModalContact, RequisiteTable, AuthMiddleware, RolesService и
ActionsService. Отдельного CRUD для стенда нет. Создание, редактирование, архив,
транзакции и аудит остаются штатными; дополнительные ограничения сеанса и
разрешённых маршрутов применяются только в локальном запуске.

## Уточнение: основной интерфейс ЕРП и ручное сохранение контакта

Предыдущий отдельный вход только в BaseContacts не соответствовал требованию
пользователя. После уточнения удалён локальный router страницы: используется
штатный src/router/index.ts, MainLayout, HeaderNav, MenuLeft и маршруты ЕРП.
В обычный BaseContacts добавлен ManagerContactEntry, который открывает существующий
ModalContact, без собственной вёрстки формы. Адрес стенда остался 127.0.0.3:4315.

Поведение «Создать в СЭП» изменено по прямому указанию пользователя: автоматическое
создание очередью заменено открытием штатной формы ЕРП. Имя, телефон и email
предзаполнены, сохранение выполняется только по кнопке самой формы. Найденный
контакт открывается в режиме редактирования, при нескольких совпадениях остаётся
явный выбор менеджера. После POST/PUT /contacts возвращённый id передаётся
существующему erp/sync для связи, без повторного создания. Права и проверки
ManagerContactsService, штатные транзакции и ActionsService сохранены.

Для ModalContact добавлены опциональные initialData и editOnOpen. Обычные
потребители остаются в прежнем режиме: просмотр имеющегося контакта, пустая
форма при обычном создании, те же поля, стили и валидация. Приватное примечание
обращения не переносится. Передача данных между вкладками проверяет origin,
исходное окно и requestId; чат также проверяет текущего сотрудника. Начальные
данные сохраняются в sessionStorage только вкладки ЕРП, контакты и токены
не передаются в URL. Настройки таблиц и история загрузок основного интерфейса
читаются через настоящие UsersService и ExcelExportHistoryService на стенде.

Проверки рабочей копии ветки manager (незакоммиченные изменения поверх
ERP client 4d3290a9c98fdf529a05373c9f64fbd3bf75e055 и chat client
959f539903a058e1fa549b53427f1461c67fcb44):

- `node scripts/verify-erp-ui.mjs` / `bun run test:erp:ui`: прошли группы проверок
  существующего контакта и перезагрузки ЕРП; предзаполненного создания и отмены
  без записи; штатной валидации, создания, связи с чатом и повторного редактирования
  без дубля; обычного режима «Информация о контакте». Ошибок JavaScript и HTTP нет.
- `bun run test:clients`: весь сценарий двух менеджеров, сообщений, файлов,
  ответственного, примечания, конфликта, отказа в доступе, штатной формы ЕРП,
  фильтров и мобильного экрана пройден. Проверка обновлена под ручное сохранение.
- Chat client: `bun x vue-tsc --noEmit` и ESLint трёх затронутых файлов прошли.
