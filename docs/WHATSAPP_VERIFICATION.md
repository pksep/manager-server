## Проверенные сценарии

WhatsApp и Telegram/MAX проверены последовательно на отдельных временных PostgreSQL, Redis и RabbitMQ. Тесты сами создают контейнеры с уникальными именами и метками владения, случайными портами на 127.0.0.1, ограничением 1 CPU и 512 МБ на зависимость. Очереди и базы рабочего стенда не используются. Метки проверяются перед удалением контейнеров. Внешний API Meta и API Чата заменены локальными тестовыми обработчиками.

Проверены подтверждение callback с Verify Token, отказ при поддельной подписи исходных байтов, приём фото с проверкой содержимого, запись через очередь, отсутствие дублей, отправка изображения в тот же канал, закрытие и открытие 24-часового окна, отсутствие продления окна при повторе старого webhook и отказ от автоматического повтора после неопределённого результата отправки. Миграция 012 применяется и откатывается штатным механизмом на пустой временной базе; бот-регрессия также проверяет отказ разрушительного отката при существующих данных.

Доставка до тестового API Чата проверяется отдельно от завершения записи в Manager: это две очереди. Первый прогон выявил преждевременное ожидание тестом результата до второй очереди, оно исправлено. Для отказов Nest используется явная проверка результата `try/catch`, так как первоначальный matcher Bun `rejects.toThrow` зависал и завершился тайм-аутом. Окончательные сценарии прошли полностью.
