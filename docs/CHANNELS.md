# Подключение ВКонтакте и Авито

Сообщения подключённых сообществ и аккаунтов появляются в СЭП Чате → «Клиенты».
Менеджеры используют обычный редактор и выбирают «Ответить через». Первый ответ
назначает менеджера один раз. Доступ определяется действующим правом ЕРП
`chat.clients:view`; отдельной роли платформы нет.

## Развёртывание

1. Обновить ЕРП и общий пакет из ветки manager (связь выбранного контакта без телефона/почты).
2. Обновить сервер Чата; применить штатной командой его миграцию
   `20260915160000-manager-channels`. Обновить клиент Чата из той же ветки.
3. Остановить прежний экземпляр manager-server, выполнить `bun run migrate:up`
   с миграционной ролью (008_channels.sql), запустить новую сборку.
   Runtime-роль получает права по `config/database-permissions.sql`.
4. Скопировать `config/channels.example.json` в приватную конфигурацию сервера;
   задать `MANAGER_CHANNELS_PATH` и реальные ID аккаунтов. Значения ключей хранятся
   в переменных окружения, JSON содержит только их имена. Включить `enabled`.
5. Настроить публичный HTTPS origin и шлюз по `config/nginx.conf`. Внешне доступны
   только `/v1/widget/*` и два callback-маршрута. `/internal` и staff API не публиковать.
   Для Авито отключить логирование полного URI на балансировщике, nginx и APM:
   URL содержит секрет. Не добавлять его в аналитику или сообщения об ошибках.

Без MANAGER_CHANNELS_PATH существующий виджет работает как раньше.
Каждому подключению нужен уникальный случайный webhook-секрет длиной 32–128
символов `[A-Za-z0-9_-]`. Нельзя менять accountId у существующего id подключения;
для другого аккаунта создаётся новый id. Отключение сохраняет историю и запрещает ответы.

## ВКонтакте

- Нужны сообщество с включёнными сообщениями, токен сообщества с правами сообщений,
  доступа к пользователям и загрузки документов, ID сообщества и строка подтверждения.
- Задать MANAGER_VK_TOKEN, MANAGER_VK_CONFIRMATION, MANAGER_VK_WEBHOOK_SECRET.
- В настройках сообщества → API → Callback API добавить
  `https://<домен>/v1/channels/vk/vk-company`, версию 5.199, свой секрет и событие
  «Входящее сообщение» (`message_new`). Подтвердить адрес при запущенном сервисе.
- Команда `bun run channels:check vk-company` проверяет доступ к API. Финальная
  проверка прав сообщений и документов — реальное сообщение и вложение в обе стороны.

## Авито

- Для товаров и работы требуется тариф «Максимальный», для услуг — «Расширенный»
  или «Максимальный» согласно документации Messenger API. Доступ проверяется в аккаунте.
- Получить client_id/client_secret основного аккаунта компании и его accountId.
  Ключи сотрудника не заменяют доступ основного аккаунта к корпоративной переписке.
- Задать MANAGER_AVITO_CLIENT_ID, MANAGER_AVITO_CLIENT_SECRET, MANAGER_AVITO_WEBHOOK_SECRET.
- `bun run channels:check avito-company` проверяет аккаунт и доступ к чатам.
- Сначала запустить сервис с активным подключением, затем задать MANAGER_PUBLIC_URL
  (`https://<домен>`) и выполнить `bun run channels:subscribe avito-company`.
  Авито проверяет callback пустым JSON; адрес должен отвечать HTTP 200 за 2 секунды.
- Полученный webhook проверяется по секретному адресу и accountId. Содержимое
  сообщения загружается авторизованным запросом из истории Авито, а не доверяется webhook.

## Возможности и ограничения

| Канал | Отправка из Чата | Приём |
| --- | --- | --- |
| ВК | Текст; проверенные документы и изображения до 20 МиБ | Текст, фото, документы; текстовая расшифровка голосового, если ВК её передал |
| Авито | Текст частями до 1000 символов; PNG/JPEG/GIF до 20 МиБ | Текст, фото, ссылки, описание объявления/местоположения |

До 10 вложений в одном ответе. Неподдерживаемое вложение показывается в Чате
с пояснением, что содержимое доступно в исходной переписке. Произвольные документы,
видео и звонки Авито не пересылаются. Редактирование и пересылка старых сообщений
во внешние каналы недоступны. Не выдаём подтверждение API за прочтение клиентом.
Переписка, отправленная сотрудником прямо из интерфейса площадки, не импортируется;
для единой истории ответы отправляются из СЭП Чата. Массовый импорт старых диалогов
до включения подписки не выполняется.

Платформы обычно не передают телефон и email. До появления обоих реквизитов клиент
определяется по паре подключение + ID пользователя площадки; одинаковые имена не
объединяются. Менеджер может сохранить/выбрать контакт в обычной форме ЕРП и связать
его с обращением. История связанного контакта видна менеджерам. Новая сессия сайта
не получает прежнюю историю. Подтверждение телефона/почты не добавляется.

## Доставка и восстановление

Уведомление подтверждается после сохранения в PostgreSQL. Повторы не создают новые
сообщения. RabbitMQ и журнал операций восстанавливают обработку после перезапуска.
Загрузка, антивирус и приватное хранение вложений переиспользуются из текущего стека.
Внешние URL ограничены доменами платформ, DNS-адрес закрепляется; локальная сеть и
небезопасные перенаправления закрыты. Ключи и ответы провайдеров не попадают в ошибки.

ВК получает постоянный `random_id` при повторе. У Авито нет документированного ключа
защиты повторной отправки: при потере подтверждения менеджер видит «Отправка не
подтверждена», проверяет исходный чат и явно подтверждает повтор. Уже подтверждённые
части не отправляются заново. Если спорная часть уже пришла, кнопка «Уже доставлена»
сохраняет подтверждение менеджера и продолжает отправку оставшихся частей без дубля.
Ошибка первого ответа удерживает последующие ответы
того же диалога, сохраняя порядок; после исправления причины нужно повторить его.

`bun run channels:status` показывает отключения и ошибки. Для исправленного сбоя
приёма: `bun run channels:retry-inbox <connectionId> <operationUUID>`. UUID берётся
из таблицы channel_inbox внутренними средствами мониторинга. После 10 попыток ошибка
требует вмешательства; настройте уведомление на failed/uncertain и рост pending.
Содержимое доставленного callback очищается через 7 дней, ключ дедупликации сохраняется.
После недоступности публичного адреса проверьте пропущенные обращения в площадках:
сервис восстанавливает принятые события, но не гарантирует повтор платформой события,
которое площадка перестала доставлять.

## Проверка

`bun run test`, `bun run test:security`, `bun run test:integration`, `bun run test:erp`,
`bun run test:channels` на отдельном локальном контуре manager. Последняя команда
подменяет только HTTP API площадок; использует настоящие PostgreSQL, Redis, RabbitMQ,
ClamAV, приватное хранилище и СЭП Чат/ЕРП. Не запускать одновременно с ручным
manager-server на 4314. Эти проверки не заменяют приёмку с реальными ключами.

Источники контрактов: [официальная схема VK](https://github.com/VKCOM/vk-api-schema),
[официальный VK SDK](https://github.com/VKCOM/vk-php-sdk),
