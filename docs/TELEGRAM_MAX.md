# Подключение Telegram и MAX к разделу Клиенты

Посетитель пишет боту компании в личный диалог. Обращение появляется в разделе
«Клиенты» СЭП Чата, оператор отвечает обычным редактором. Ответ уходит в тот же
диалог того же бота. Для сотрудников действует существующее право на раздел
«Клиенты», новые роли не требуются.

## Создание ботов

В Telegram откройте официальный [BotFather](https://t.me/BotFather), выполните
`/newbot` и задайте название и имя бота. Сохраните выданный токен в защищённом
хранилище сервера как `MANAGER_TELEGRAM_TOKEN`. Числовой ID бота, не имя с `@`,
нужно записать в `accountId`. ID возвращает метод `getMe`; команда проверки ниже
сверяет его с конфигурацией. В стандартном токене Telegram ID также находится
перед двоеточием.

В MAX создайте чат-бота в [MAX для бизнеса](https://business.max.ru/) по
[официальной инструкции](https://dev.max.ru/docs-api). Получение доступа и создание
бота зависят от требований MAX к аккаунту организации. Выпустите токен бота,
сохраните его как `MANAGER_MAX_TOKEN`. В `accountId` укажите `user_id` бота из
ответа `GET /me`, а не ID сообщества или диалога. Команда проверки сверяет этот ID.

Не присылайте токены в переписку и не помещайте их в публичный JSON, сайт или
репозиторий. Для каждого бота сгенерируйте свой случайный секрет уведомлений
из 32–128 символов `A-Z`, `a-z`, `0-9`, `_`, `-`. Сохраните их отдельно как
`MANAGER_TELEGRAM_WEBHOOK_SECRET` и `MANAGER_MAX_WEBHOOK_SECRET`.

## Настройки сервера

Администратор добавляет две записи в существующий приватный файл каналов,
указанный в `MANAGER_CHANNELS_PATH`. Не заменяйте весь файл: ВК и Авито должны
остаться в нём. Образцы записей есть в `config/channels.example.json`:

```json
[
  {
    "id": "telegram-company",
    "platform": "telegram",
    "name": "Компания в Telegram",
    "accountId": "123456",
    "enabled": true,
    "webhookSecretEnv": "MANAGER_TELEGRAM_WEBHOOK_SECRET",
    "tokenEnv": "MANAGER_TELEGRAM_TOKEN"
  },
  {
    "id": "max-company",
    "platform": "max",
    "name": "Компания в MAX",
    "accountId": "654321",
    "enabled": true,
    "webhookSecretEnv": "MANAGER_MAX_WEBHOOK_SECRET",
    "tokenEnv": "MANAGER_MAX_TOKEN"
  }
]
```

Замените числовые ID на реальные. Значения секретов передаются только через
защищённое окружение процесса Manager. Также задайте
`MANAGER_PUBLIC_URL=https://manager.pksep.ru`.

## Порядок выкладки и подписка

1. Обновите Chat Server, принимающий источники `telegram` и `max`, и Chat Client
   с названиями каналов и фильтрами. Для этой доработки миграций Chat Server нет.
2. В Manager выполните штатное `bun run migrate:up` с миграционной ролью.
   Миграция `010_telegram_max.sql` расширяет допустимые каналы, не меняя переписку.
   Затем запустите новую сборку с конфигурацией и секретами.
3. Разрешите на внешнем HTTPS-шлюзе два адреса ниже. Образец есть в
   `config/nginx.conf`. Шлюз должен передавать секретные заголовки ботов, но не
   журналировать их. Внутренние `/internal` и staff API наружу не открывайте.
4. В окружении Manager выполните команды проверки и регистрации:

```sh
bun run channels:check telegram-company
bun run channels:check max-company
bun run channels:subscribe telegram-company
bun run channels:subscribe max-company
bun run channels:status
```

Адреса уведомлений, которые регистрирует команда:

| Бот      | Адрес                                                            | Заголовок проверки                |
| -------- | ---------------------------------------------------------------- | --------------------------------- |
| Telegram | `https://manager.pksep.ru/v1/channels/telegram/telegram-company` | `X-Telegram-Bot-Api-Secret-Token` |
| MAX      | `https://manager.pksep.ru/v1/channels/max/max-company`           | `X-Max-Bot-Api-Secret`            |

Секрет в адрес добавлять не нужно. Регистрация Telegram сохраняет ожидающие
уведомления (`drop_pending_updates=false`), но заменяет прежний webhook этого бота.
Не подключайте к Manager бота, который одновременно обслуживается другим сервисом.
Для Telegram не запускайте параллельно получение событий через `getUpdates`.

MAX использует актуальный API `https://platform-api2.max.ru`. Для HTTPS нужны
доверенные сертификаты; если сервер не доверяет цепочке API MAX, администратор
добавляет официальный корневой сертификат в доверенное хранилище среды запуска.
Отключать проверку сертификатов нельзя.

## Проверка работы

Напишите каждому боту из обычного аккаунта, затем отправьте фото и PDF до 20 МиБ.
В «Клиентах» проверьте текст, источник и вложения, ответьте текстом и файлом.
Ответ должен прийти отправителю в соответствующем мессенджере. Повторная доставка
одного уведомления не должна создавать второе сообщение.

Отключение записи через `enabled=false` сохраняет историю и запрещает новые
ответы через этот канал. После подключения другого бота используйте новый `id`:
менять аккаунт существующего подключения нельзя.

## Возможности и восстановление

Поддержаны личные сообщения пользователей, фото и проверяемые документы до
20 МиБ, до 10 вложений в одном ответе. Длинные ответы разбиваются на части:
Telegram до 4096 символов, MAX до 4000. Группы, каналы, сообщения от ботов,
редактирование и удаление сообщений не импортируются. Для голосовых, видео и
других неподдерживаемых вложений оператор видит пояснение вместо самого файла.
Прочтение сообщения на стороне клиента не подтверждается.

Крупное фото Telegram свыше 10 МиБ или фото, отклонённое из-за пропорций,
отправляется как документ без уменьшения оригинала.

Старые диалоги до подключения не импортируются. Ответы, отправленные вручную
из приложения мессенджера, не добавляются в историю СЭП. Телефон и email не
угадываются, одинаковые имена клиентов не объединяются. URL скачивания Telegram
с токеном бота не сохраняется в переписке или нормализованном событии.

Принятое уведомление сначала сохраняется в базе, затем обрабатывается очередью.
При временном отказе запрос повторяется с задержкой. Ошибки приёма после исчерпания
попыток видны в `channels:status`; после устранения причины используется
`bun run channels:retry-inbox <connectionId> <operationUUID>`.

Если связь пропала во время отправки и площадка не подтвердила результат,
автоповтор останавливается со статусом «Отправка не подтверждена». Проверьте
диалог клиента и подтвердите уже доставленную часть либо разрешите повтор.
Это защищает от одинаковых сообщений при перезапуске. Подтверждение требуется
только для спорного ответа; другие диалоги продолжают обрабатываться.

Откат миграции 010 при существующих подключениях Telegram/MAX запрещён, чтобы
не потерять историю. Для отключения используйте конфигурацию, не удаление данных.

## Проверки разработки

`bun run test` выполняет все модульные тесты Manager.
`bun run test:bots` создаёт отдельные временные PostgreSQL, Redis и RabbitMQ на
случайных loopback-портах и удаляет только собственные контейнеры. Нужны Docker
и образы `postgres:18-alpine`, `redis:8-alpine`, `rabbitmq:4-alpine`.
HTTP площадок и Chat Server в этом тесте заменены контрактными локальными
ответами. Приёмка с настоящими ботами выполняется отдельно после настройки ключей.

Контракты: [Telegram Bot API](https://core.telegram.org/bots/api),
[webhook Telegram](https://core.telegram.org/bots/webhooks),
[подписки MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions),
[сообщения MAX](https://dev.max.ru/docs-api/methods/POST/messages),
[файлы MAX](https://dev.max.ru/docs-api/methods/POST/uploads),
[официальный SDK MAX](https://github.com/max-messenger/max-bot-api-client-ts).
