# Журнал подтверждённых ошибок manager-server

## Новая форма без имени требует непустого названия профиля Чата (14.10.2026)

- **Поведение:** поле имени стало необязательным, а телефон и email объединены
  в одно поле. Прежний сервер требовал имя и оба контакта при `contactPolicy: all`;
  пустое имя также нарушало контракт при доставке канонического профиля в Чат.
- **Предотвращение:** принимать один корректный контакт. Старые значения
  `all` и `name-and-one` сохранены для совместимости конфигов и теперь используют
  одинаковое правило. Старая форма с двумя контактами тоже принимается.
  Имя в реквизитах может оставаться пустым, но отображаемое название карточки
  и профиль доставки получают «Посетитель сайта». Не подменять реальные реквизиты
  этим текстом и не открывать старую историю по одному совпавшему контакту.
- **Автоматическая проверка:** `bun run test` проверяет новый и прежний контракт,
  пустое имя, неверные значения и непустой профиль доставки. `bun run test:avito`
  включает изолированный сценарий публичного виджета с PostgreSQL, Redis,
  RabbitMQ и подменённым HTTP Чата: телефон без имени, email без имени,
  отказ пустому/неверному контакту до создания обращения и совместимость старой формы.
  `bun run test:delivery-recovery` проверяет прежние правила доставки и повторов.
- **Выкладка:** сначала обновить manager-server, затем manager-client.
  Новый виджет со старым сервером не совместим по правилам обязательных полей.
  Миграции базы и изменения прав не требуются. Полный многосервисный стенд
  с настоящими ERP и Чатом этими изолированными проверками не заменяется.

## Ошибка доставки навсегда удерживает следующие сообщения (12.10.2026)

- **Поведение:** одно недоставленное сообщение останавливает следующие сообщения
  того же обращения даже после восстановления связи. По сообщению оператора,
  за ошибкой в проде накопились девять сообщений; он предложил ручной пропуск.
- **Причина в коде:** после десяти любых ошибок `DeliveryWorker` переводил операцию
  в `failed`. Проверка порядка ожидала завершения всех предыдущих операций,
  включая `failed`, а автоматическое восстановление очереди выбирает только
  `pending` и просроченные `working`. Получалась бессрочная блокировка.
- **Предотвращение:** временные и неопределённые результаты повторять с ограниченной
  паузой, не исчерпывая доставку. Только явный HTTP 400/422 из Чата отделять как
  отклонённое сообщение; сохранять его в журнале ошибок, не блокируя следующие.
  Не менять его статус на доставленное и не удалять данные. Для старых `failed`
  доступен существующий ручной повтор. Не ослаблять порядок/подтверждение спорных
  исходящих сообщений ВК и Авито.
- **Автоматическая проверка:** полный `bun run test` и отдельный
  `bun run test:delivery-recovery` на собственных временных PostgreSQL/RabbitMQ.
  Длинный сбой и ошибка перед девятью сообщениями воспроизводятся без доступа
  к рабочим базам и без отправки реальным пользователям.
- **Приёмка:** тест подменяет HTTP Чата, поэтому проверку реального Chat Server,
  мониторинга и продовой очереди выполнять отдельно после выкладки.

## Успешный ответ истории Авито не проходит валидацию (13.10.2026)

- **Поведение:** Авито отвечает успешно и возвращает `{ messages, meta }`,
  но входящее сообщение не появляется в разделе «Клиенты».
- **Причина:** обработчик `/messenger/v3/.../messages/` проверял весь ответ
  как массив. Интеграционный тест тоже подменял ответ голым массивом,
  поэтому не воспроизводил настоящий формат страницы V3.
- **Предотвращение:** проверять объект страницы и каждый элемент `messages`;
  сохранять ограничения размера, поиск по страницам и сверку автора/направления.
  Сохранить совместимость старого ответа-массива с той же проверкой элементов.
  Не принимать служебные метаданные за сообщения. Тестовые ответы должны
  соответствовать формату внешнего API. HTTP 200 с ошибкой нашего разбора
  не является подтверждением платёжного отказа или необходимости смены тарифа.
- **Автоматическая проверка:** `bun run test` включает сообщения с/без `meta`,
  поиск на следующей странице, пустой/повреждённый ответ и чужого автора.
  `bun run test:avito` проверяет приём webhook, запись сообщения и доставку
  в подменённый HTTP Чата на отдельных временных зависимостях.
- **Приёмка:** реальные аккаунт, подписка Авито и доставленные до исправления
  события проверяются отдельно после выкладки. Эти тесты не меняют подписки
  площадки и не отправляют сообщения реальным клиентам.

## Проверка каналов падает до запроса к площадке (09.10.2026)

- **Поведение:** проверка и регистрация каналов могут завершаться
  `CHANNEL_NETWORK_ERROR` до получения ответа API. Webhook-секрет и ключи
  площадки при этом не являются причиной этого конкретного сбоя.
- **Причина:** закреплённый DNS lookup всегда вызывал callback с одиночным
  адресом и семейством IP. При `options.all=true` сетевой стек ожидает массив
  объектов `{ address, family }`. Регрессионный тест на Bun 1.3.14 подтвердил
  нарушение контракта и отказ настоящего локального TCP-соединения.
- **Предотвращение:** при `all=true` возвращать массив только с ранее
  проверенным адресом; иначе сохранять одиночный формат. Не выполнять
  повторное разрешение имени и не обходить запрет внутренних адресов.
- **Автоматическая проверка:** `bun test tests/unit/channel-lookup.test.ts`
  проверяет оба формата для IPv4/IPv6, отсутствие `all` и настоящее локальное
  TCP-соединение с автоматическим выбором семейства и без него. Тест не
  требует ключей, баз данных, очередей или изменения подписок площадок.
- **Приёмка в рабочем окружении:** после обновления сборки выполнить
  `bun run channels:check avito-npo-automotiv` с уже настроенными переменными
  окружения. Проверка локального транспорта не подтверждает доступность
  API и права аккаунта в рабочем окружении.
