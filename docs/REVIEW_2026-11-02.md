### Изоляция серверных проверок

Chat Server запускался с окончательным src только для чтения в `pksep-ai-chat-server:main-refresh-20261030`, с `--network none`, `--cpus 2`, `--memory 3g`, NODE_ENV=test и заменённым entrypoint. Рабочие базы и хранилища недоступны.

ERP запускался в `pksep-ai-erp-server:main-refresh-20261030`, с `--network none`, 2 CPU и 4 ГБ. Окончательные src ERP и src общего пакета копировались внутрь временного контейнера до тестов. Зависимости package.json/bun.lock совпадают с образом. Команда: `npm run test:unit -- --runInBand`; используется тот же штатный script, поскольку в production-образе нет исполняемого Bun. Общий пакет пересобирается этим script внутри контейнера. Сборка и тесты не пишут в исходники хоста.

Board запускался с окончательными src, scripts, migrations и конфигурацией в `pksep-ai-board-server:time-report-20261026`. Временная внутренняя Docker-сеть, новые PostgreSQL/Redis без опубликованных портов, собственная база `board_archive_test_*`, 1 CPU и 512 МБ на зависимость, 2 CPU и 3 ГБ на тесты. Команды: `npm run test -- --runInBand`, затем `npm run build`; это штатные scripts того же package.json. Тесты идут последовательно. Перед очисткой проверяется уникальная метка владельца контейнеров и сети. Ресурсы рабочего стенда не используются и не удаляются.

Manager сам создаёт отдельные временные контейнеры для интеграционных тестов. Модульные тесты AI и Client используют свои тестовые подмены и временные данные. Расширенный браузерный набор Client выполнялся по одному исполнителю на отдельном порту 5181 с подменами API; новый реальный диалог WhatsApp не создавался.

### Неуспешные и незавершённые проверки

- Chat Server: три ошибки в LiveKit и тесте стикеров воспроизведены также без нового WhatsApp-кода. В прежнем отдельном сравнении исходной версии 16 успешно и те же 3 ошибки. Все 69 пропущенных тестов остаются непроверенными. Сами старые ошибки в этот PR не исправлялись.
- Board: `src/tests/app.e2e-spec.ts` из main импортирует отсутствующие ERP-модули и `src/utils/methods/test-helper`; набор не загружается. Изменений этого файла в diff нет. Три пропущенных проверки учётных записей не считаются выполненными.
- Client: обе ошибки в неизменённом `tests/theme-init.spec.ts` вызваны отсутствующим navigator в изолированном контексте. Отдельно взятые из origin/main тест, theme-init.js и index.html дают 1 успешный и те же 2 упавших теста.
- Первоначальный расширенный браузерный прогон дал 16 успешных и 6 упавших из 22: четыре проверки счётчика с неполной старой фикстурой и две проверки подтверждений на мобильном экране, ожидающие видимый пункт истории. Фикстура счётчика исправлена, повторный связанный прогон дал 10/10. Подтверждения повторно проверены на компьютере, 9/9. Две проверки мобильных подтверждений остаются неуспешными; они не объявляются проверенными. Полный браузерный набор Client не запускался.
- Первые попытки контейнерного прогона Board/ERP не были результатом тестов приложения: production-образы не содержат Bun и всех файлов для тестов. Окончательные прогоны выше используют штатные scripts через npm и явно подключённые тестовые файлы. После добавления scripts/migrations тесты миграций Board прошли. Промежуточные 409 успешных/2 упавших из-за отсутствующих scripts не выдаются за окончательный результат.

По этим причинам публикация PR не означает полной готовности всех сервисов к production. Замечания и пропуски сохранены явно; общие наборы с ошибками не названы успешными.
