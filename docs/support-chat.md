# Постоянные чаты поддержки

В разделе «Клиенты» сервер Чата выдаёт менеджерам системную папку «Поддержка».
Её состав определяют зарегистрированные подключения. Удаление, переименование,
перестановка и ручное изменение состава запрещены сервером.

Одна установка «Умного пресса» использует один постоянный чат для всех своих
авторизованных пользователей. Первое подключение: «Умный пресс - Тула».
Повторные открытия и перезапуски сохраняют идентификаторы клиента, обращения
и топика. Подготовка выполняется при запуске manager-server и не создаёт
фиктивных сообщений. Если Чат ещё недоступен, подготовка повторяется.
Менеджер может ответить, когда клиент закрыл окно: ответ сохраняется до его возвращения.

## Настройка

1. Выпустить совместимые версии chat_server, chat_client и manager-client.
   В manager-server применить штатную миграцию 009, затем запустить новую версию.
2. Добавить профиль из `config/support.example.json` в общий массив
   `MANAGER_SITES_PATH`, сохранив остальные сайты. В рабочем окружении заменить
   локальные адреса на адрес пресса и HTTPS origin виджета.
3. Создать отдельный случайный ключ не короче 32 символов для этой установки.
   В manager-server установить `MANAGER_SUPPORT_SMART_PRESS_TULA_KEY`;
   в sp_server — `SUPPORT_CLIENT_KEY` с тем же значением.
4. В sp_server установить:
   - `SUPPORT_CLIENT_ID=smart-press-tula`;
   - `SUPPORT_SERVICE_URL=https://manager.example.com` (без `/v1`);
   - `SUPPORT_WIDGET_URL=https://widget.example.com/widget.html`.
5. Выпустить sp_client и sp_server. Открыть поддержку из хедера авторизованного
   пользователя и проверить появление чата в «Клиенты → Поддержка».

Без этих настроек окно сообщает «Чат поддержки ещё не настроен».
Служебный ключ не попадает в клиентскую сборку, iframe URL или сообщения.
Браузер получает ограниченный токен только этой переписки через сервер пресса.
Токен передаётся виджету через postMessage с проверкой origin, source и instance.
Гостевой доступ истекает; открытие окна продлевает его без создания новой переписки.
Ротация ключа отзывает прежний токен после следующего доверенного подключения.

## Следующие клиенты

Для каждой установки добавить отдельный профиль с уникальными `id`,
`support.clientId` и отдельным ключом. Имя `support.name` задаёт название
постоянного чата. Установка не может выбирать идентификатор другой установки
через публичный API пресса. Не переиспользовать профиль и ключ между клиентами.

Виджет поддержки — отдельный компонент `SupportWidget.vue` в manager-client,
который использует существующую переписку `Widget.vue`. Вход —
`widget.html#mode=support`. Отправка текста, файлов, история, подтверждения
и ответы сотрудников проходят через обычные канонические методы manager/Чата.
Выбор пользователей и упоминания отключены.

Черновик и состояние незавершённой отправки сохраняются в памяти приложения
при закрытии окна, включая выбранные файлы. Выход из учётной записи и перезагрузка
страницы очищают черновик; отправленная история остаётся на сервере.
Повтор отправки использует прежний идентификатор операции.

Для общего чата действует лимит соединений `MANAGER_WS_IP_CONCURRENCY`,
а не лимит трёх вкладок обычного посетителя сайта. Общий и IP-лимиты,
проверка файлов и ограничения частоты сообщений сохраняются.

## Локальная проверка

`bun run test` проверяет все модульные тесты manager-server.
`bun run test:security` проверяет весь набор безопасности и откат миграций.
`bun run test:support` проверяет первое подключение, повтор после сбоя,
параллельные открытия, несколько операторов, продление доступа и изоляцию клиентов.
Для последнего теста нужен отдельный контур: PostgreSQL на loopback:56441
с исходной базой `manager_support_qa`, Redis `redis://127.0.0.1:6391/1`
и отдельный RabbitMQ vhost. Тест создаёт и удаляет только свою базу
`manager_support_test_<timestamp>`, использует порты 44315 и 44515.

Сквозная браузерная проверка в sp_client включается `SUPPORT_CHAT_LIVE=true`.
Она требует отдельно поднятые локальные версии сервисов на 3216, 44314, 44310
и 44501 и `SUPPORT_CHAT_QA_DIRECTORY` с приватными `sp-auth.json` и
`staff-auth.json`. Не использовать рабочие данные и ключи. Проверяются реальные
текст, файл, ответ менеджера, неизменность папки, повторное открытие и узкий экран.
